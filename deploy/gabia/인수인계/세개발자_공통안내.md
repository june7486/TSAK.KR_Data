## 4. 시스템 구조 — 30초 요약

```
사용자 → [프록시 서버]  →  NAS (데이터 정본)
         Python 3          39.123.241.4:5001
         프레임워크 없음    /92_Tiger_app_data/TSAK_인가자관리
         /api/* 256개
         Flutter 웹앱 정적 서빙
```

**가장 중요한 사실: DB 는 서버에 없습니다.**
서버 로컬 디스크는 대부분 **캐시**(지워져도 재생성)입니다.
그래서 이전이 "데이터 마이그레이션"이 아니라 **"코드 + 빌드물 배포"** 로 끝납니다.

**그리고 그게 위험입니다.** 이전하면 서버↔NAS 구간이 **공인 인터넷**을 지납니다.

### 규모 (실측)

| 항목 | 값 |
|---|---|
| Dart | 178개 파일 / 135,182줄 / 화면 56개 |
| 프록시 | 30,109줄 (1.4MB) |
| API | 256개 엔드포인트 |
| 데이터 | NAS `db/` JSON 38개 |
| 백업 | NAS `backups/` 432개 (보존 정책 없음) |

## 5. 역할 분담 (제안 — 조정 가능)

### 개발자 A — 실행 환경 · 시작 명령

- 필요한 패키지 목록 확정 (**`openpyxl` 포함 여부 반드시 확인**)
- 환경변수 4개 정리: `TSAK_PORT` / `TSAK_STATIC_DIR` / `TSAK_APP_ROOT` / `TSAK_STATE_DIR`
- 시작 명령이 아무 설명 없이 따라 할 수 있는 수준인지 검토
- 릴리스 구조(`releases/` + `current` 심볼릭 링크 + `shared/state`) 이해·검증

**⚠️ 이미 발견된 함정:** `requirements.txt` 가 오랫동안
"표준 라이브러리만 사용 (필수 의존성 없음)" 이라고 **거짓**으로 적혀 있었습니다.
실제로는 `openpyxl` 을 세 곳에서 import 합니다(엑셀 명단 업로드/견본/재무).
없으면 앱은 뜨는데 엑셀 기능만 조용히 죽습니다. → 현재 수정 완료. **다른 곳에 같은 거짓이 없는지 확인해 주세요.**

### 개발자 B — 데이터 저장 위치 · 백업·복구

- NAS `db/` 38개 컬렉션의 역할 정리 (무엇이 어떤 화면에 쓰이는지)
- `backups/` 432개 무제한 누적 → **보존 정책** 검토
  (제안: 일 7 + 주 4 + 월 6 ≈ 30개. 아직 승인 전)
- 복구 절차와 **걸리는 시간** 측정
- 복구 시 **무엇이 되살아나고 무엇이 안 되는지 한계까지** 정리

**⚠️ 이미 발견된 함정:** `_bwrite_bg` 에서 두 번째 저장이 **조용히 사라지던** 버그
(`IndexError` 를 `except: pass` 가 삼킴). 현재 수정 완료.
→ 저장 계층에 같은 "조용한 삼킴"이 더 있는지 확인해 주세요.

### 개발자 C — 무중단 시험 · 보안

- `test.tsak.kr` 같은 **임시 도메인으로 인증서까지 검증**하는 절차 설계
- 이전 후 점검 목록 작성
- 보안 항목 검토 (아래는 이미 확인된 것)

**⚠️ 이미 확인된 보안 사항:**
- `nas.pw` 와 앱 비밀번호가 **동일** (③ 승준님 결정 필요)
- NAS 자체서명 인증서 → 종전엔 검증을 통째로 껐음(`CERT_NONE`)
  → 현재 **지문 고정(pinning)** 으로 변경
- NAS 인증서 만료: **2027-05-02**. 갱신하면 지문이 바뀌어 접속 거부됨
  → `TSAK_NAS_CERT_SHA256` 으로 임시 통과 절차 필요
