## 2. 시스템 개요

```
[사용자 브라우저]
      │  https://tsak.kr  (현재는 www → 샌드박스 포워딩)
      ▼
┌─────────────────────────┐
│  TSAK 프록시 서버         │  ← 이전 대상. Python 3, 프레임워크 없음
│  · Flutter 웹앱 정적 서빙  │     ThreadingHTTPServer
│  · /api/* 256개 엔드포인트 │
└───────────┬─────────────┘
            │  HTTPS (인증서 지문 고정)
            ▼
┌─────────────────────────┐
│  Synology NAS            │  ← ★데이터 정본(원본)★
│  39.123.241.4:5001       │
│  /92_Tiger_app_data/     │
│      TSAK_인가자관리/     │
└─────────────────────────┘
            │
            ▼  (선택)
      Google Drive
```

### 핵심: **DB 는 서버에 없습니다**

프록시 서버는 **상태가 거의 없는 중계자**입니다.
데이터 정본은 NAS 이고, 서버 로컬 디스크는 대부분 **캐시**(지워져도 다시 만들어짐)입니다.

이게 이전을 가볍게 만드는 이유이자, **위험을 만드는 이유**이기도 합니다.
이전하면 서버↔NAS 구간이 **공인 인터넷을 지나기 때문**입니다(아래 6절).

### 규모 (실측)

**→ 저장소를 받으실 때 이 두 가지가 최신인지 먼저 확인해 주세요.** 사본은 조용히 낡습니다.

## 4. 실행 방법

```bash
# 의존성 — requirements.txt 를 믿지 마세요 (아래 5절)
sudo apt install -y python3-openpyxl        # Debian/Ubuntu
# 또는 pip3 install -r api/requirements.txt

# 실행
export TSAK_PORT=5071
export TSAK_STATIC_DIR=~/tsak/current/web
export TSAK_APP_ROOT=~/tsak/current/api
export TSAK_STATE_DIR=~/tsak/shared/state   # ★반드시 릴리스 밖★
cd ~/tsak/current/api && python3 -u proxy_server.py
```

### 릴리스 구조 (배포 방식)

```
~/tsak/
├── releases/
│   ├── 20261120_115037/{api,web}     # 과거
│   └── 20261120_115106/{api,web}     # 현재
├── current -> releases/20261120_115106    # ← 심볼릭 링크만 교체 (원자적)
└── shared/
    ├── config.json                    # 자격증명 (릴리스 밖)

    └── app.log
```

**`TSAK_STATE_DIR` 을 릴리스 안에 두면 롤백할 때 세션·업로드가 사라집니다.**

## 5. ⚠️ 반드시 알아야 할 함정 5가지

### ① `requirements.txt` 는 거짓말이었습니다 (수정함)

종전 주석: `# 표준 라이브러리만 사용합니다 (필수 의존성 없음)`

실제로는 `openpyxl` 을 **세 곳에서 최상위 import** 합니다.
- 엑셀(.xlsx) 인원 명단 업로드 파싱 ← 실사용 핵심
- 견본 xlsx 생성
- 통합 재무 엑셀 내보내기

**없으면 앱은 정상 기동합니다. 엑셀 기능만 조용히 죽습니다.**
사용자가 처음 그 기능을 쓸 때 터집니다. → 필수로 선언하고 세팅 시 검사합니다.

### ② 롤백이 한 번도 동작한 적 없었습니다 (수정함)

```bash
R='\$HOME/tsak'     # single quote 안에서는 \$ 가 확장되지 않음
```
롤백 블록 **한 곳만** 따옴표가 달라 `$HOME` 이 글자 그대로 남았고,
항상 `✗ 이전 릴리스가 없습니다` 로 끝났습니다. **장애 때 눌러도 아무 일이 없었습니다.**

### ③ 릴리스 정리가 방금 만든 릴리스를 삭제했습니다 (수정함)

`ls -1dt | tail -n +6` 이 최신순이라 **최신을 지웠습니다.**
6번째 배포에서 롤백 대상이 사라집니다.

### ④ 두 번째 저장이 조용히 사라졌습니다 (수정함)

`slot = [content_bytes]` (길이 1)인데 `prev[1]` 에 쓰려 해 `IndexError`.
그 예외를 `except: pass` 가 삼켜 **2차 저장이 영구 유실**됐습니다.

### ⑤ 원격 명령에 백틱을 쓰면 실행됩니다

```bash
R "echo \`whoami\`"     # ← 원격에서 명령 치환으로 실행됨
```
리허설에서 `Is a directory` 오류로 확인했습니다. **원격 문자열에 백틱 금지.**

## 6. 이것만은 결정이 필요합니다 (③ 승준님 결정 필요)

### 6-1. NAS 비밀번호가 앱 비밀번호와 같습니다

실측 확인: `nas.pw` == `auth.app` (**동일한 값**)

지금은 같은 샌드박스에서 사설 경로로 붙지만, 이전하면 **공인 인터넷**을 지납니다.
하나가 뚫리면 둘 다 뚫립니다. **이전 전이 마지막 교체 적기입니다.**

### 6-2. NAS 방화벽에 가비아 IP 허용이 필요합니다

이전 후 서버가 NAS 에 붙으려면 NAS 방화벽/보안 설정에서 **가비아 서버 IP 를 허용**해야 합니다.
지금은 샌드박스 IP(`170.106.202.227`)만 통과할 가능성이 있습니다.

> 참고: NAS 에는 이미 차단 IP `77.90.185.54`(독일 봇)가 등록되어 있습니다. 정상 동작입니다.

### 6-3. NAS 인증서 지문 고정 — 갱신 시 대응

NAS 는 자체서명 인증서(`CN=synology`, 2027-05-02 만료)를 씁니다.
종전에는 검증을 통째로 껐습니다(`CERT_NONE`). 이전 후 그건 무방비입니다.

→ **지문 고정(pinning)** 으로 바꿨습니다. 자체서명이어도 바꿔치기는 차단됩니다.
현재 지문: `6b3a018e…6ac7e52b` (SHA-256)

**NAS 인증서를 갱신하면 지문이 바뀌어 접속이 거부됩니다.**
그때는 `TSAK_NAS_CERT_SHA256=<새지문>` 환경변수로 임시 통과 후 코드 상수를 갱신하세요.
로그에 기대값/실제값이 함께 찍히므로 원인 파악은 어렵지 않습니다.

정책 3단계: `pin`(기본) / `strict`(공인 CA 체인) / `off`(응급 전용)

### 6-4. 도메인 전환 방식 — 3가지 중 선택

| 방식 | 위험 | 인증서 발급 |
|---|---|---|
| ① hosts 파일 | 가장 낮음 (내 PC만) | ❌ 불가 |
| ② `test.tsak.kr` 임시 도메인 | 낮음 | ✅ 가능 (권장) |
| ③ IP 직접 접속 | 낮음 | ❌ 불가 |

**인증서까지 검증하려면 ② 를 권합니다.** 실패해도 기존 서비스는 영향받지 않습니다.

## 7. 백업·복구 절차

### 3중 구조

| 층 | 대상 | 도구 | 보관 |
|---|---|---|---|
| ① 코드·빌드물 | 로컬 전체 372MB | `backup_snapshot.sh` / `restore_snapshot.sh` | 12개 |
| ② 릴리스 | 서버 코드 | `deploy_gabia.sh --rollback` | 최근 5개 |
| ③ 데이터 정본 | NAS JSON 38개 + 사진 | NAS + Google Drive | 상시 |

### 데이터 백업의 실제 모습

NAS `backups/` 에 **432개**가 쌓여 있습니다. 종류별로는 `members` 413개,
`eunha_members` 12개, 나머지 소수입니다.

**⚠️ 보존 정책이 없습니다.** 2026-09-26 부터 무제한 누적입니다.
파일 하나는 작지만(JSON) 개수가 계속 늘어납니다.
→ 일 7 + 주 4 + 월 6 ≈ 30개 수준의 정책을 제안했고, **아직 적용 전**입니다(승인 대기).

### 복구 절차

```bash
# 1) 스냅샷 목록
bash restore_snapshot.sh --list

# 2) 복원 (안전 스냅샷을 먼저 만든 뒤 진행)
bash restore_snapshot.sh --latest
bash restore_snapshot.sh 20261120_115037
```

복원 순서: 무결성 검사 → **안전 스냅샷 선행** → 임시 전개 → 필수 5파일 확인
→ 교체 → 사후 검증(web 개수, qr.html md5, SHA-256)

### 이전 시 실제로 옮길 것

**`merch_img_upload/` (80MB, 64개 파일) + `.sessions.json`** 뿐입니다.

나머지는 캐시라 **따라오면 안 됩니다**:
