## 1-5. 실행

```bash
# 수동 실행 (배포 스크립트 없이 확인만 할 때)
cd ~/tsak/current/api && \
  TSAK_STATIC_DIR=../web TSAK_PORT=5071 python3 -u proxy_server.py

# 시스템 서비스 등록 (재부팅 후 자동 기동)
sudo systemctl enable --now tsak
sudo systemctl status tsak
sudo journalctl -u tsak -n 50
```

`setup_gabia_server.sh`가 유닛 파일을 만들어 줍니다. 유닛은 **`current` 심볼릭링크를 참조**하므로 릴리스 교체 시 유닛을 고칠 필요가 없습니다.

**기동 성공 판정 — 이 6줄이 나와야 정상** (실제 샌드박스 로그)

```
[state] 상태 루트 = /home/tsak/tsak/shared/state (코드 ... 와 분리됨)
[tls]   NAS TLS = pin (지문 고정 6b3a018e77f99b24…)
[backend] NAS(read-through cache) + store '.../gdrive_store'
[sess]  디스크에서 세션 13개 복원 (재기동 후 로그인 유지)
[mem-guard] 시작 · 현재 RSS=136MB (경고 1800MB / 정리 3000MB)
TSAK NAS proxy on 0.0.0.0:5071 (queue=512)
```

**어느 줄부터 다른지** 알려주시면 원인을 좁힐 수 있습니다.

## 1-6. 수신 주소·포트·헬스 — 실측

```python
# proxy_server.py:30012
return ThreadingHTTPServer(("0.0.0.0", port), Handler)
```

| 항목 | 값 |
|---|---|
| 바인드 주소 | `0.0.0.0` (모든 인터페이스) |
| **포트** | **5071** |
| 포트 우선순위 | `TSAK_PORT` 환경변수 > `config.json` `port` > 기본 5071 |
| 헬스 경로 | **`GET /api/health`** (`/readyz`, `/version` API 없음. `/version.json`은 정적 파일) |

> ### "샌드박스 주소의 5071이 실제 수신 포트인가"
>
> **예. 추정이 아니라 실측입니다.**
>
> ```
> $ ss -tlnp | grep 5071
> LISTEN 0 512 0.0.0.0:5071 0.0.0.0:* users:(("python3",pid=154538,fd=11))
>
> $ curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:5071/api/health
> 200
> ```
>
> 샌드박스 인그레스가 80/443 → 5071로 넘겨줄 뿐, **앱이 듣는 포트는 5071**입니다.
> 가비아 nginx 업스트림을 `127.0.0.1:5071`로 맞추십시오.
> 다른 포트를 쓰려면 `TSAK_PORT`만 바꾸면 되고 **코드 수정은 불필요**합니다.

## 1-7. 별도 API·백그라운드 작업 필요 여부

**웹 화면만으로는 동작하지 않습니다. 서버 프로세스 1개가 반드시 필요합니다.**

| 구성 | 필요 여부 | 설명 |
|---|---|---|
| 정적 웹 (`build/web`) | 필요 | Flutter 화면 |
| **API 서버 (`proxy_server.py`)** | **필수** | API 256개 + 정적 파일 서빙을 **한 프로세스가 겸함** |
| DBMS | 불필요 | 파일 기반 JSON |
| 별도 배치·크론 | **불필요** | crontab 비어 있음 (실측) |
| 메시지 큐·캐시 서버 | 불필요 | — |

**프로세스 내부 스레드** — `python3 -u proxy_server.py` **하나** 안에서 돕니다. 별도로 띄울 것은 없습니다.

| 스레드 | 주기 | 역할 | 없으면 |
|---|---|---|---|
| `_serve_guard` | 상시 | `serve_forever` 예외 시 자동 재기동 | 요청 1건의 예외로 서버가 죽음 |
| `_mem_guard_loop` | 30초 | RSS 감시, 임계 초과 시 임시파일 정리 | 메모리 누적 시 OOM 위험 |
| `_hist_guard_loop` | 5초 | 집계 캐시 지연 쓰기 | 집계 반영이 늦어짐 |
| `_warm_bg` | 기동 1회 | JSON 캐시 예열 | 첫 요청이 느림 |
| `sess-save` | 변경 시 | 세션을 디스크에 저장 | 재기동 시 로그아웃 |

> 샌드박스에 `.watchdog.pid`(10월 13일, PID 46601)가 남아 있으나 **이미 죽은 파일**입니다. 상시 프로세스는 `proxy_server.py` **1개뿐**입니다.

## ②-3. NAS 인증서 2027-05-02 만료 — 갱신 시 앱이 멈춥니다

**실측한 NAS 인증서**

```

**이번에 바꾼 것**: 종전 코드는 `ssl.CERT_NONE` — **인증서 검증을 아예 안 했습니다.** 샌드박스 안에서는 NAS가 사설망이라 견딜 만했지만, 가비아로 옮기면 **NAS 트래픽이 공용 인터넷을 지납니다.** 그대로 두면 중간자 공격에 무방비입니다.

**그래서 지문 고정(fingerprint pinning)으로 교체했습니다.**
- 기본 `pin` 모드: 인증서 지문을 대조, 다르면 **즉시 연결 차단**
- 사설 자체서명서도 지문만 맞으면 통과 (공인 CA 불필요)
- 검증 완료: 정상 통과 ✅ / 지문 불일치 시 차단 ✅

> ⚠️ **2027-05-02에 NAS 인증서가 만료됩니다.**
> 갱신하면 지문이 바뀌어 **앱 전체가 NAS 접속 실패로 멈춥니다.** 증상: 모든 화면 "불러오기 실패".
> 갱신 시 `TSAK_NAS_CERT_SHA256`에 새 지문을 넣고 재기동하면 됩니다.
> **이 사실을 운영 인수자에게 반드시 전달해 주십시오.**

>

**2단계 — 전환 시점 (승인 후)**

| 방식 | 내용 | 추천 |
|---|---|---|
| **A. 짧은 입력 동결** | 전환 30분 전 공지 → 입력 중단 → 최종 백업 → 전환 → 재개 | **권장** |
| B. 변경분 추적 | 최종 백업 이후 변경된 파일만 골라 재적용 | 위험 |

**A를 권고하는 이유**: `merch_img_upload/`와 `.sessions.json`이 서버 로컬에 있어 "A 서버에서 올린 이미지"가 "B 서버"에는 없습니다. 동결 없이 옮기면 **동결 시점 이후 업로드가 유실**됩니다. 30분 동결이 가장 안전합니다.

T+30  재개 공지

CORS_ALLOW_ORIGINS = [
