## 먼저 — 지적하신 내용 중 사실관계 정정 2건

검토를 정확히 하려면 이 두 가지가 먼저 맞춰져야 합니다.

### ① "별도 샌드박스 주소로 이동하는 페이지" — 맞습니다 (실측 확인)

```http
GET http://www.tsak.kr/  →  200 OK (Server: Apache)
<meta http-equiv="refresh" content="0;url=https://5071-i0wgdg3il1ohzxyvietj8-0e616f0a.sandbox.novita.ai/">
<title>TSAK 한국범스카우트중앙회</title>
```

EUC-KR 메타 리프레시 한 줄짜리 페이지입니다. **실제 앱은 이 서버에 없습니다.**
www.tsak.kr 은 "간판"이고, 앱은 샌드박스가 서빙합니다.

**→ www 레코드를 먼저 바꾸면 안 된다는 판단에 동의합니다.** 다만 이유가 하나 더 있습니다(아래 ②).

### ② "인증서 이름 불일치" — 이건 인증서 문제가 아니라 **아직 우리 서버가 아닙니다**

```
subject = C=KR, ST=Gyeonggi-do, L=Seongnam-si, O=Gabia,Inc., CN=*.gabia.com
issuer  = GlobalSign RSA OV SSL CA 2018
```

`*.gabia.com` 은 가비아의 **주차(parking) 인증서**입니다. 즉 121.254.178.232 의 443 포트는
아직 TSAK 앱이 아니라 가비아 주차 페이지가 응답합니다.

**그러므로 이전 전에 "인증서를 고칠" 대상은 없습니다.** 가비아 서버에 우리 앱을 올리고
`tsak.kr` 용 인증서를 **새로 발급**하는 것이 맞습니다. 기존 인증서를 이어받는 방식이 아닙니다.

> 검증 항목도 바뀝니다: "인증서 경고 없이 접속"이 아니라
> **"발급한 인증서의 CN/SAN 에 `tsak.kr` 과 `www.tsak.kr` 이 모두 들어있는가"** 입니다.
> `www` 를 쓰실 거면 SAN 에 반드시 포함해야 합니다(요즘 브라우저는 CN 을 무시합니다).

## Q2. 실행 환경과 시작 명령

### 런타임 실측

| 항목 | 값 |
|---|---|
| 언어 | Python 3 — **표준 라이브러리만** 사용 |
| 웹 서버 | `ThreadingHTTPServer` (프레임워크 없음) |
| 앱 빌드물 | Flutter Web 정적 파일 (`build/web`) |
| 프레임워크 | 없음 (Flask/Django/FastAPI 미사용) |

```bash
# gabia_deploy/api/start.sh — 실제 시작 명령
export TSAK_STATIC_DIR="${TSAK_STATIC_DIR:-$here/../web}"
export TSAK_PORT="${TSAK_PORT:-5071}"
cd "$here" && exec python3 -u proxy_server.py
```

### 의존성 — `requirements.txt` 는 "없음"이라고 적혀 있지만 **정확하지 않습니다**

```
# TSAK 프록시는 파이썬 표준 라이브러리만 사용합니다 (필수 의존성 없음).
```

실제로는 **`openpyxl` 이 세 곳에서 최상위 import** 됩니다.
(엑셀 인원 명단 업로드 파싱 / 견본 xlsx 생성 / 재무 엑셀 내보내기 — 전부 실사용 기능입니다)

```python
proxy_server.py:6311   import openpyxl                       # 업로드 파싱
proxy_server.py:17354  import openpyxl                       # 재무 엑셀
proxy_server.py:17355  from openpyxl.styles import Font, ...  # 스타일
```

**→ 가비아에 `py3-openpyxl` (또는 `pip install openpyxl`) 설치가 필요합니다.**
이걸 빼면 앱은 뜨는데 **엑셀 업로드/내보내기가 조용히 실패**합니다.
`requirements.txt` 를 `openpyxl` 로 고쳐 두는 것을 권합니다(이번엔 조회 단계라 수정 보류).

### 포트 — 5071 은 "샌드박스 사정"이지 가비아 포트가 아닙니다

`5071` 은 코드 기본값(`CONF.get("port", 5071)`)일 뿐이고 `TSAK_PORT` 로 덮어쓸 수 있습니다.
**가비아 포트는 확정하지 않았습니다.** 서버에서 열려 있는 포트와 방화벽 정책을 보고 정해야 합니다.

### 필요한 환경변수 4개

```bash
TSAK_PORT        # 서비스 포트
TSAK_STATIC_DIR  # 웹앱 위치 (예: ~/tsak/current/web)
TSAK_APP_ROOT    # 코드 루트 (예: ~/tsak/current/api)
TSAK_STATE_DIR   # ★상태 루트 (예: ~/tsak/shared/state) ← 반드시 릴리스 밖
```

`TSAK_STATE_DIR` 을 릴리스 안에 두면 **롤백할 때 세션·업로드가 사라집니다.**
이번에 코드/상태 분리를 넣고 릴리스 A→B→A 실측 시험으로 확인했습니다.

## Q3. DB·업로드 파일의 실제 저장 위치

### 결론: DB 는 **가비아 서버에 두지 않습니다.** 정본은 NAS 와 Google Drive 입니다.

```
앱(브라우저) → 가비아 서버(프록시) → NAS  https://39.123.241.4:5001
                        ↘ gdrive (root_id 설정됨)
```

`config.json` 키 구조(값 제외):

```
nas.base      = https://39.123.241.4:5001
nas.user      = tigerscout
nas.base_path = /92_Tiger_app_data/TSAK_인가자관리
backend       = auto
port          = 5071
gdrive.root_id, base_path (설정됨) / service_account·client_secret·oauth_token (빈값)
auth.masterHash (설정됨) / auth.app (설정됨)
```

### 이 구조가 이전에 주는 의미 — 좋은 소식과 나쁜 소식

**좋은 소식:** DB 를 옮길 필요가 없습니다. 가비아 서버는 **상태가 거의 없는 프록시**입니다.
이전이 "데이터 마이그레이션"이 아니라 "코드 + 빌드물 배포"로 끝나는 이유입니다.

**나쁜 소식:** 가비아→NAS 구간이 **공인 인터넷을 지납니다.** 지금은 같은 샌드박스에서
사설 경로로 붙지만, 이전 후에는 그렇지 않습니다. 여기에 두 가지 위험이 겹칩니다.

| 위험 | 내용 | 상태 |
|---|---|---|
| TLS 검증 꺼짐 | NAS 접속에 `CERT_NONE` (자체서명 인증서 회피) | **미수정 · 위험** |
| 비밀번호 공유 | `nas.pw` 와 `auth.app` 이 **동일한 값** | **미수정 · 위험** |

이전하면 이 두 가지가 "같은 방 안의 문제"에서 **"인터넷에 노출된 문제"** 로 바뀝니다.
이전 전에 결정하셔야 할 항목으로 올립니다(아래 Q5).

### 서버 로컬 디스크에 실제로 쌓이는 것 (실측)

가비아 서버로 **가져가야 하는 상태(=`shared/state`)는 작습니다.** 나머지는 캐시입니다.

| 경로 | 크기 | 성격 | 이전 필요 |
|---|---|---|---|
| `merch_img_upload/` | 80 MB (64개) | **사용자 업로드 원본** | ✅ 반드시 |
| `.sessions.json` | 작음 | **로그인 세션** | ✅ (또는 재로그인 허용) |
| `.json_mirror/` | 8.3 MB (34개) | NAS JSON 사본 캐시 | ❌ 재생성 |
| `merch_img/` | 3.4 MB | 시드 상품 이미지 | ⭕ 코드에 포함 가능 |
| `.thumb_cache/` | 127 MB | 썸네일 | ❌ 재생성 |
| `.media_cache/` | 110 MB | 미디어 | ❌ 재생성 |
| `.static_compress_cache/` | 1.2 GB | 압축 정적파일 | ❌ 재생성 |

## Q4. 백업·복구 방법 — **3중**입니다

| 층 | 대상 | 도구 | 주기 |
|---|---|---|---|
| ① 코드·빌드물 스냅샷 | 로컬 전체 (372 MB) | `backup_snapshot.sh` / `restore_snapshot.sh` (12개 보관) | 배포 전 자동 |
| ② 릴리스 롤백 | 서버 코드 | `deploy_gabia.sh --rollback` (심볼릭 링크 교체) | 즉시 |
| ③ 데이터 정본 | 인원·행사·상품 JSON, 사진 | NAS (`39.123.241.4:5001`) + Google Drive | 상시 |

### ⚠️ 백업에서 발견한 결함 (이번에 고침)

**롤백이 한 번도 동작한 적이 없었습니다.**

```bash
R='\$HOME/tsak'     # ← single quote 안에서는 \$ 가 확장되지 않음
```

롤백 블록 **한 곳만** 따옴표가 달라 `$HOME` 이 글자 그대로 남았고, 항상
`✗ 이전 릴리스가 없습니다` 로 끝났습니다. **장애 때 눌러도 아무 일이 안 일어나는 상태**였습니다.

같은 리허설에서 추가로 나온 것들도 고쳤습니다.

- 롤백 헬스체크가 3초 만에 포기 → 정상 기동 중인데 `헬스 실패` 거짓 경보
- 릴리스 정리가 **방금 만든 릴리스**를 삭제 → 6번째 배포에서 롤백 불가
- 상태 지문이 캐시까지 세어 정상 배포를 `데이터 유실 가능성` 으로 표시

자격증명이 없어 **가짜 ssh/scp/systemctl + 로컬 가상 서버**로 A→B→A 전환을
실제로 돌려 확인했습니다. 결과는 통과입니다.

**한계:** 가상 서버에서 검증한 것입니다. **실제 가비아 SSH·systemd·nginx·certbot 경로는 아직 미검증입니다.**

## Q5. 기존 주소를 유지한 채 가비아에서 시험하는 방법

### 핵심: `tsak.kr` 을 건드리지 않고 검증하는 순서

DNS 를 바꾸지 않고 확인할 수 있는 방법이 3가지 있습니다. 위험한 것부터 아래로 갑니다.

**① hosts 파일 (가장 안전, 즉시)**

```
# PC 의 C:\Windows\System32\drivers\etc\hosts  (관리자 권한)
<가비아IP>  tsak.kr
<가비아IP>  www.tsak.kr
```
내 PC 에서만 가비아로 붙습니다. 남들은 기존 주소 그대로. 끝나면 두 줄 삭제.
**단, 인증서 발급(Let's Encrypt HTTP-01)은 외부에서 접근해야 하므로 hosts 로는 안 됩니다.**

**② 임시 도메인으로 인증서까지 검증 (권장)**

```
test.tsak.kr  →  가비아IP  (A 레코드, TTL 300)
```
`test.tsak.kr` 로 인증서를 발급·검증하고 앱이 정상 동작하는지 확인한 뒤,
마지막에 `tsak.kr`/`www.tsak.kr` 만 같은 IP 로 바꿉니다.
**실패해도 기존 서비스는 한 번도 영향받지 않습니다.**

**③ IP + 포트 직접 접속 (인증서 없이)**
`http://<가비아IP>:<포트>/` 로 HTML·API 만 먼저 확인. 인증서는 나중.

### DNS 전환 시 반드시 지킬 것

| 항목 | 이유 |
|---|---|
| **`www` 를 먼저 바꾸지 말 것** | 지금 www 가 앱의 유일한 입구입니다. `tsak.kr` 부터. |
| TTL 을 미리 낮추기 (300초) | 전환 후 되돌리는 시간을 줄입니다. 최소 1시간 전에. |
| 전환 전 기존 레코드 **스크린샷/메모** | 되돌릴 좌표를 잃지 않으려면. |
| 메타리프레시 페이지를 **먼저 교체하지 말 것** | 앱이 가비아에서 뜨는 걸 확인한 뒤 마지막에. |
| 인증서 SAN 에 `tsak.kr` + `www.tsak.kr` 둘 다 | 요즘 브라우저는 CN 무시. 하나만 있으면 경고. |

### 이전 후 확인해야 할 것 (앱이 "열리는가"만 보면 부족합니다)

앱은 **같은 origin 상대경로**(`/api/...`)로 API 를 부릅니다. 코드에 서버 주소가 박혀 있지 않습니다.
그래서 이전해도 앱 코드 수정은 필요 없습니다. 대신 아래를 확인해야 합니다.

- [ ] `/api/health` 200 (프록시 살아있음)
- [ ] `/api/config` **401** (인증 게이트가 살아있음 — 200 이면 보안 구멍)
- [ ] 로그인 → 세션 유지 (`.sessions.json` 이 `shared/state` 에 있는지)
- [ ] 상품 이미지 표시 (NAS 경유 — **가비아→NAS 인터넷 구간 첫 실전**)
- [ ] 사진 업로드 (역방향 쓰기 — 읽기보다 실패하기 쉬움)
- [ ] 엑셀 업로드/내보내기 (**`openpyxl` 설치 확인** — 누락 시 조용히 실패)
- [ ] 서비스워커 캐시 무효화 (구버전이 남아 있으면 이전이 안 보임)
- [ ] QR 코드가 새 주소로 생성되는지

### 이전 후 반드시 다시 봐야 할 설정

**QR 공개주소.** 웹에서는 현재 origin 을 쓰므로 자동으로 맞습니다.
하지만 `memorial.html` 등에 **샌드박스 주소가 하드코딩된 폴백**이 2곳 있습니다
(`home_screen.dart`, `lock_screen.dart`). 웹에서는 origin 이 우선이라 문제없지만,
**APK 를 빌드할 때는 `SERVER_BASE` 를 새 주소로 주셔야 합니다.**

```bash
SERVER_BASE=https://tsak.kr bash scripts/build_apk.sh   # 이미 이렇게 쓰도록 되어 있음
```
